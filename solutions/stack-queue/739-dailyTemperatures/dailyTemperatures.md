# 739.dailyTemperatures(每日温度)

## 题目
给定一个整数数组 temperatures，返回数组 answer，其中 answer[i] 表示第 i 天之后，**下一个更高温度**出现在几日后。若之后没有更高温度，answer[i] = 0。

示例:
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]

## 思路：单调栈（**存下标**）

维护一个**单调递减栈**——从栈底到栈顶，温度依次降低。**栈里存的是"下标"**。

遍历每一天 i：
- 只要 `temperatures[i] > temperatures[栈顶]`，就说明**栈顶那天等到了它的第一个更高温**：
  - 弹出 idx，`res[idx] = i - idx`（相差几天）
  - 继续弹（可能一次"结账"好几天）
- 处理完，把 i 压栈

扫描结束，栈里剩下的下标都没等到更高温 → 保持 0。

## 代码
```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> res(n, 0);
        stack<int> st;                       // 存【下标】，不存温度
        for(int i = 0; i < n; i++){
            while(!st.empty() && temperatures[i] > temperatures[st.top()]){
                int idx = st.top(); st.pop();
                res[idx] = i - idx;          // 距离 = 今天 - 那天
            }
            st.push(i);
        }
        return res;
    }
};
```

## 复杂度
- 时间：$O(n)$——每个下标入栈、出栈各一次
- 空间：$O(n)$——栈

## 要点

### 1. 为什么"存下标"而不是"存温度"

**因为答案要的是"差几天"。**

只存温度的话，等它被弹出来时，你**不知道它原来在第几天**，就没法算距离。

> **存下标 = 同时存了"值"和"位置"。**（值随时能用 `temperatures[idx]` 取回来；位置丢了就找不回来。）

这就是你说"对存下标理解更深了"的地方——**不是习惯，是必需**。

### 2. 和 496 的关键区别

| | 496 下一个更大元素 I | **739 每日温度** |
|---|---|---|
| 数组元素 | 各不相同 | **可能有重复** |
| 存什么 | 值（配哈希表）| **下标** |

496 里值唯一，所以"值 → 答案"能直接存进 map；739 里温度会重复，**值不能当 key**，只能用下标。**重复是关键。**

### 3. 为什么栈是"递减"的

栈里排队的，都是"**还没等到更高温**"的日子。
新来一个更热的，会把栈顶那些**更冷的**一次性全部结账——所以留在栈里的，从栈底到栈顶**越来越冷**（递减）。

> 栈底 = 更早、更热；栈顶 = 更近、更冷。

### 4. 每个元素只进出一次
所以总时间是 O(n)，不是 O(n²)——这又是一次"**用栈维护状态**"，跟你 496 学的是同一个招式。
