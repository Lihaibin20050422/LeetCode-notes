# 242.isAnagram(有效的字母异位词)

## 题目
给定两个字符串 s 和 t，编写一个函数判断 t 是否是 s 的**字母异位词**。
字母异位词：两个字符串中**每个字符出现的次数都相同**，只是排列顺序不同。
（题目保证字符串只包含小写字母）

示例:
输入: s = "anagram", t = "nagaram" → true
输入: s = "rat",     t = "car"     → false

## 思路：一个 26 长度的计数数组，**一加一减**

1. **长度不同** → 直接 `false`；
2. 遍历一遍：**s 的字符 +1，t 的字符 −1**；
3. 最后看数组是不是**全是 0**——是 0 说明两边"收支平衡"，是异位词。

> **关键洞察：不需要两个哈希表。**
> s 加、t 减，最后看**账平不平**就行。

## 代码
```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.length() != t.length()) return false;
        int cnt[26] = {0};
        for (size_t i = 0; i < s.length(); i++) {
            cnt[s[i] - 'a']++;      // s 记账
            cnt[t[i] - 'a']--;      // t 销账
        }
        for (int i = 0; i < 26; i++) {
            if (cnt[i] != 0) return false;
        }
        return true;
    }
};
```

## 复杂度
- 时间：$O(n)$
- 空间：**$O(1)$**（26 个格子，常数）

## 要点

### 1. 为什么用数组，而不是 `unordered_map`
**因为值域小且固定**——只有 26 个小写字母。

- 数组：`O(1)` 随机访问，无需哈希计算，常数极小；
- `unordered_map`：要哈希、要处理冲突，**杀鸡用牛刀**。

> 这就是 **"能用数组当哈希，就别用 map"**。

对照你之前两道：
- **1. 两数之和 / 169. 多数元素**：值域**大且不固定** → 只能用 `unordered_map`；
- **242**：值域**小且固定**（26 个）→ 数组完胜。

**判断标准：值域能不能开成数组？能，就用数组。**

### 2. 一加一减 vs 两个哈希表

| | 空间 | 最后怎么判 |
|---|---|---|
| 两个表 | 两个表 | 要**逐字母比较两个表** |
| **一加一减** | **一个表** | 只需**看是否全 0** |

少一半空间、少一次遍历。

### 3. 它和"摩尔投票"的相似处

你说得对——**两者都是"抵消 / 记账"的思想**：
- 摩尔投票：**不同的两个数**两两抵消，剩到最后的就是多数；
- 242：**s 的字符减 t 的字符**，抵消到最后看账平不平。

> **"最后看余数/看账"这个思路，是计数类问题的通用武器。**

### 4. 边界
- **长度不同** → 一票否决（先判，省时间）；
- **空串** → `""` 与 `""` 是异位词（都空，账平）；
- **只有小写字母** → 由题目保证，`s[i]-'a'` 一定落在 `[0,25]`。
  若输入可能含其他字符，就得换 `unordered_map` 或开更大的数组。
