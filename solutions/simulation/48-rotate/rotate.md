# 48. 旋转图像

## 题目

给定一个 `n × n` 的二维矩阵，将它**原地**顺时针旋转 90°。

示例：
```
[[1,2,3],      [[7,4,1],
 [4,5,6],  →    [8,5,2],
 [7,8,9]]       [9,6,3]]
```

## 思路：**先转置，再每行反转**

```
顺时针 90° = 转置 + 水平翻转
```

两步都很便宜，而且都是原地操作。

### 为什么这样是对的（坐标推导）

顺时针 90° 的目标映射：`(i, j) → (j, n-1-i)`

拆成两步：

| 步骤 | 映射 |
|---|---|
| ① 转置 | `(i, j) → (j, i)` |
| ② 每行反转（水平翻转） | `(r, c) → (r, n-1-c)` |

合起来：`(i,j) --转置--> (j,i) --反转--> (j, n-1-i)` ✅ **正好是顺时针 90°**

## 代码

```cpp
void rotate(vector<vector<int>>& matrix) {
    int n = matrix.size();

    // ① 转置：只遍历上三角
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            swap(matrix[i][j], matrix[j][i]);
        }
    }

    // ② 每行反转
    for (int i = 0; i < n; i++) {
        reverse(matrix[i].begin(), matrix[i].end());
    }
}
```

## 关键坑：`j` 从 `i + 1` 开始

```cpp
for (int j = i + 1; j < n; j++)   // ← 不是 j = 0
```

**转置只需要遍历上三角**（`i < j` 的部分）：

- `j` 从 `i+1` 开始 → 每对 `(i,j)` 和 `(j,i)` 只交换一次 ✅
- `j` 从 `0` 开始 → 已经交换过的对会**再交换回去**，转置失效 ❌

> **转置的对称性意味着：走一半就够了，走全部等于没走。**
> 这是原地操作里最常见的"做了两遍等于没做"。

## 复杂度

- 时间 $O(n^2)$
- 空间 $O(1)$（原地）

## 要点

### 1. 三个方向的旋转变换

| 目标 | 做法 |
|---|---|
| **顺时针 90°** | 转置 + **每行反转** |
| **逆时针 90°** | 转置 + **每列反转**（等价于上下翻转 + 转置）|
| **180°** | 上下翻转 + 左右翻转（或转两次） |

**记一个就够：顺时针 = 转置 + 左右翻。**

### 2. 你一开始想的"绕圈旋转"也是对的

那种做法叫**分层四元轮换**：从外圈往内圈，每层把四个位置的元素轮换一次：

```
matrix[top][i] → matrix[i][right] → matrix[bottom][...] → ...
```

**同样是原地、O(n²)、O(1)。** 但要注意四点：

- 每层只转 `n - 1 - 2*层` 个元素（**不转整条边，否则四个角转两次**）
- 四个位置的索引关系容易写错
- 递归形式更难调试

> **转置 + 反转，是用"两步简单的全矩阵操作"换掉了"一步复杂的局部操作"。**
> 能用后者解决的，就别用前者——**这是工程上的"可读性优先"。**

### 3. 边界

| 输入 | 结果 |
|---|---|
| `1×1` | 不变 |
| `2×2` | `[[a,b],[c,d]]` → `[[c,a],[d,b]]` |
