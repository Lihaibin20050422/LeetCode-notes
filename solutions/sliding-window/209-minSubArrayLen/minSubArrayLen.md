# 209. 长度最小的子数组

## 题目

给定一个**正整数**数组 `nums` 和目标值 `target`，找出**和 ≥ target** 的**长度最小**的连续子数组，返回它的长度；不存在则返回 0。

示例：`target = 7, nums = [2,3,1,2,4,3]` → `2`（子数组 `[4,3]`）

## 思路：右指针扩张，左指针收缩

窗口 `[left, right]` 维护"当前这一段的和"：

1. `right` 一路往右走，`sum` 累加；
2. **只要 `sum >= target`**，就先更新答案，再把 `left` 往右挪一格、`sum` 减去它；
3. 缩到不满足条件为止，继续扩右指针。

**核心只有一句：右指针负责"够不够"，左指针负责"能不能更短"。**

### 为什么是 `while` 不是 `if`

条件满足后，可能连续缩好几次才刚好不满足。
比如 `target = 5, nums = [2,3,1,1,1,1,1]`：右指针走到下标 2 时 `sum = 6`，缩一次是 5、还能再缩，写成 `if` 只会缩一次，答案就错了。

## 代码

```cpp
int minSubArrayLen(int target, vector<int>& nums) {
    int left = 0, sum = 0, minLen = INT_MAX;
    int n = (int)nums.size();
    for (int right = 0; right < n; right++) {
        sum += nums[right];             // 右指针扩张
        while (sum >= target) {         // 满足就缩，可能连续缩多次
            minLen = min(minLen, right - left + 1);
            sum -= nums[left];          // 先记长度，再缩左端
            left++;
        }
    }
    return minLen == INT_MAX ? 0 : minLen;
}
```

## 复杂度

- 时间 **$O(n)$**
- 空间 $O(1)$

### 为什么是 $O(n)$，不是 $O(n^2)$

外面一层 `for` 看着是 $n$ 次，里面还套了 `while`，但**两把指针都只往右走、不回头**：

> 每个元素**最多被右指针加进来一次、被左指针移出去一次**，总操作次数 ≤ $2n$。

这叫**均摊分析**：`while` 的总次数不是 $n \times n$，而是整个循环期间加起来不超过 $n$。

## 要点

### 1. 这道题成立的前提：全是正数

因为正数，所以**窗口越长，和越大**（单调）。
"和 ≥ target"一旦成立，再往左缩只可能变小，边界是单调移动的——这才是双指针能用的根本原因。

**如果数组里有负数**，右扩不一定变大、左缩不一定变小，窗口就"不单调"了。
那时要用 **前缀和 + 单调队列** 求"最短子数组和 ≥ target"，这是另一道题的做法。

> 记一句：**滑动窗口 ≈ 单调性 + 两个不回头指针。**

### 2. 更新答案的位置

`minLen` 必须在 `sum -= nums[left]` **之前**更新，因为此时窗口仍是 `[left, right]`。
先减再更新，就会把左端多减掉一个。

### 3. 边界

| 情况 | 结果 | 怎么来的 |
|---|---|---|
| 无解 | `0` | `minLen` 仍是 `INT_MAX`，最后统一判一次 |
| 空数组 | `0` | 循环不进 |
| 单个元素就够 | `1` | `right - left + 1 = 1` |

### 4. `int n = (int)nums.size();`

`nums.size()` 是 `size_t`，和 `int right` 比较会触发符号警告；长度超过 `INT_MAX` 的数组本来也不存在，直接转一次更干净。
